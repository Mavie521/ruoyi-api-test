📖 项目背景与目标

🎯 业务目标

  • 为现有 pytest 自动化框架搭建 Web 管理界面

🗄️ 数据模型设计

case_cache（用例缓存）

nodeid TEXT UNIQUE — tests/test_role.py::TestRole::test_list_roles module TEXT — tests/test_role.py class_name TEXT — TestRole func_name TEXT — test_list_roles markers TEXT — JSON: ["p0","smoke"]

runs（执行记录）

run_tag TEXT UNIQUE — run-20260725-001 status TEXT — pending|running|passed|failed markers / env / extra_args total_tests / passed / failed / skipped started_at / finished_at / output_log

run_results（用例结果）

run_id FK → runs outcome: passed|failed|skipped|error test_name / nodeid duration_sec / message

决策点 为什么用 SQLite 而不是复用 MySQL？运行历史非业务数据，零配置、便携、标准库免依赖。面试话术："运行元数据和业务数据分库存储，职责分离。"

⚙️ 三大核心流程

1. 用例收集 collector.py

subprocess.run(["python", "-m", "pytest", "tests/", "--collect-only", "-q"]) → 解析 : : 格式或树形格式 → DELETE FROM case_cache → INSERT 新数据

2. 执行测试 runner.py

asyncio.create_task(后台): ThreadPoolExecutor → subprocess.Popen(cmd, shell=False) → 读取 output → parser.py 解析 junitxml → 入库 → allure generate → 更新 runs.status

决策点 为什么用 ThreadPoolExecutor 而非 asyncio.create_subprocess_exec？ Windows ProactorEventLoop 兼容性问题。线程池方案跨平台一致。

3. 状态轮询 run_routes.py

前端 setInterval(2s) → GET /api/runs/{id}/status → {status,total,passed,failed} status=running → 继续 / status=passed|failed → 停止 + 加载详情

🔁 高频踩坑模式

  • 跨平台地狱：Windows ↔ Linux 双环境导致的 asyncio 差异 + 端口可达性 + 路径分隔符
  • 路由配置陷阱：FastAPI 路由顺序、Mount vs 函数路由优先级、MIME 类型自动判断不准
  • 版本兼容隐雷：Python 3.9 语法限制、Node 16→18 升级、pytest 输出格式差异

💡 经验总结

  1. 先测目标环境：开发机确认端口后立刻在目标机验证，避免"Windows 通 Linux 挂"的延迟发现
  2. 防御性解析：pytest 输出格式不是标准 API，必须同时兼容新旧格式
  3. 路由即文档：FastAPI /docs 自动生成应作为联调第一入口，curl 逐个测接口
  4. 尽量标准库：sqlite3、xml.etree.ElementTree、subprocess 都在标准库里，零依赖就是零风险

🧹 孤儿进程清理

问题场景

  • uvicorn 崩溃 → pytest 子进程变孤儿 → 端口占用、数据库 running 残留
  • 网络超时 → asyncio 任务卡死 → 后续请求全部 409

解决方案

  • 启动清理 lifespan 中 pkill -f pytest + UPDATE runs
  • 手动清理 仪表盘 + 执行历史双入口 🧹 按钮
  • 每次重启 自动重置 running → error + 标记中断原因

代码实现

# main.py lifespan 启动钩子 if platform.system() == "Windows": subprocess.run(["taskkill", "/F", "/IM", "pytest.exe"]) else: subprocess.run(["pkill", "-f", "pytest"]) c.execute("UPDATE runs SET status='error' WHERE status='running'")

🔍 双轮匹配策略

第一轮：精确匹配

规则: api/user/info 请求: /mock/api/user/info → ✅ 命中 请求: /mock/api/user/123 → ❌ 不命中

第二轮：通配符 * 匹配

规则: api/user/* 请求: /mock/api/user/123 → ✅ 命中 请求: /mock/api/user/456 → ✅ 命中 # * 转正则 [^/]+ 匹配单段路径 regex = "^api/user/[^/]+$"

匹配优先级

精确匹配 > 通配符匹配。同路径既有精确规则又有通配符规则时，精确规则优先。
